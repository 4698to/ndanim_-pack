# DIYFace UV 空间蒙皮权重复制 · 使用分享

更新日期：2026-10-29

## 1 它解决什么问题

把**源模型已经修好的蒙皮权重**，按 **UV 空间**复制到 **UV 布局相同、但顶点数/点序/拓扑不同**的目标模型上。

典型场景：

- 源模型精修过面部权重，目标模型是重新布线或不同 LOD 的成品
- 源和目标都有左右重叠 UV（左右眼、上下唇共 UV），必须避免左右骨骼权重串侧
- 源模型不必留在目标场景里，可以先导出成文件，再在目标场景导入

## 2 文件与启动

| 文件 | 作用 |
| --- | --- |
| `DIYFaceSkinUVTransfer.py` | 主脚本，界面与读写逻辑 |
| `DIYFaceSkinUVSemantics.py` | 骨骼名称解析、映射与候选判断，必须与主脚本同目录 |
| `DIYFaceSkinUVTransfer.ms` | 3ds Max 启动入口，可重复运行（会关闭旧窗口并重载模块） |

在 3ds Max 里运行 `DIYFaceSkinUVTransfer.ms` 打开工具窗口。修改脚本后重新运行同一个 `.ms` 即可生效，不需要重启 Max。

## 3 三步上手

### 第一步：源模型导出

1. 在场景中选中**源模型**，点工具里的「使用当前选择」
2. 「权重文件」点「另存为...」指定一个 `.json` 路径
3. 「导出模式」保持默认 **UV v3（跨拓扑/消歧）**
4. 「骨骼命名镜像标识」填**源模型**自己的标识，例如 `_L_` 和 `_R_`（不带引号）
5. 「消歧」保持默认 **骨骼左右 + 候选一致性**
6. 点「导出权重」

「当前模型参考对」一行会显示自动选中的左右骨骼，例如 `参考对：FACIAL_L_Eye / FACIAL_R_Eye`。没有显示时点旁边的「骨骼解析预览」检查名称是否被识别。

导出完成后，源模型可以移出场景，后续只用这个 json 文件。

### 第二步：目标模型预览

1. 选中**目标模型**，点「使用当前选择」
2. 选好同一个权重文件
3. 「骨骼命名镜像标识」改成**目标模型**的标识（命名风格不同也没关系）
4. 「写入模式」按需选择，首次建议「覆盖」
5. 点「预览（不修改场景）」

预览不会改权重、不加骨骼、不改骨骼上限，可以放心反复试。

### 第三步：正式导入

确认预览数字合理后，点「导入权重」。场景修改（写权重、补骨骼、改骨骼上限）打包成**一次 Undo**，按 `Ctrl+Z` 可整体撤销。

## 4 参数速查

| 参数 | 说明 | 建议 |
| --- | --- | --- |
| UV 通道 | 源导出与目标导入使用的 UV 通道 | 与模型实际通道一致，默认 1 |
| 导出模式 · UV v3 | 保存 UV、权重、左右分区数据，支持跨拓扑 | 默认用这个 |
| 导出模式 · 兼容格式 | 只按顶点序号保存，顶点数必须一致、点序必须一致 | 仅老流程兼容用 |
| 写入模式 · 覆盖 | 用新权重替换目标顶点权重 | 常用 |
| 写入模式 · 仅未加权 | 只处理当前没有权重的顶点 | 保留手工权重 |
| 写入模式 · 混合 | 现有权重与传入权重按 50/50 平均 | 新旧权重过渡 |
| 复制方式 · UV 空间 | 按 UV 位置找源面对应点 | 主方案 |
| 复制方式 · 3D 距离 | 按三维最近点复制，不看 UV | 无 UV 时用，不做左右消歧 |
| 目标 UV 水平翻转（U） | 源与目标 UV 左右镜像时勾选 | 只翻 U，**不交换左右骨骼** |
| 消歧 · 骨骼左右 + 候选一致性 | 先用骨骼左右分区过滤候选，再比权重是否一致 | 默认，有左右骨骼时用 |
| 消歧 · 仅候选一致性 | 不做左右分区，只接受权重一致的候选 | 骨骼没有左右命名时用 |
| 材质分区 | 用材质 ID 进一步区分重叠 UV | 源目标材质含义一致时才勾选 |
| 骨骼命名镜像标识 | 左/右各填一个字面标识，如 `_L_` / `_R_` | 区分大小写，不加引号 |

透明参数：中线带宽 `0.001`、候选权重一致性容差 `1e-5`，均已内置，不在界面暴露。

## 5 骨骼命名怎么匹配

工具只做**名称语义**判断，不改名、不交换权重。

自动识别（大小写不敏感）：

- 单字母带分隔：`FACIAL_L_Eye` / `FACIAL_R_Eye`、`Eye.L` / `Eye-R`
- 完整单词：`Left_Eye` / `Eye_Right`
- 驼峰边界：`LeftEye` / `EyeRight`

**镜像标识只在自动识别不足时兜底**，按区分大小写的字面替换配对。例如骨骼叫 `eyeA` / `eyeB`，可填 `eyeA` / `eyeB` 让它们各自被识别为左右。两个都留空则完全依赖自动解析；只填一个、两个相同或互相包含都会直接报错，不会静默降级。

不会误判：`Upper`、`Lower`、`Roll`、`Clavicle`、`Leftover` 这类词不会被当成左右。

源和目标命名风格不同可以混合使用：导出填源标识，导入填目标标识，工具按“本名相同 + 同侧”自动对应，例如 `FACIAL_L_Eye` → `FACIAL_Left_Eye`。名称含冲突标识（如 `L_Eye_R`）、重名、找不到对应骨骼都会报告，不会猜。

## 6 结果怎么看

状态行示例：

```text
预览（场景未修改）：可写 4210，实际写入 0，保留 132，UV 未覆盖 5，歧义 3/1/2。
```

| 字段 | 含义 |
| --- | --- |
| 可写 | 能确定唯一权重的顶点数 |
| 实际写入 | 正式导入时真正写入的数量（预览恒为 0） |
| 保留 | 因缺 UV、歧义、必要采样失败等原因**保留原权重**的顶点 |
| UV 未覆盖 | 目标顶点 UV 在源 UV 里找不到对应面 |
| 歧义 `a/b/c` | 中线歧义 / 同侧重叠歧义 / 其他候选不一致 |
| missing_bones | 源文件里有、目标场景找不到的骨骼，权重会损失并汇总 `lost_weight_sum` |
| invalid_reference | 参考骨骼对无效，左右分区未生效 |

详细原因点开结果弹窗的「显示详细信息」查看，包含逐顶点原因。

**命中率高不等于结果正确**：若 `保留` 数量明显偏大，优先看是骨骼没映射上，还是 UV 本身不重叠。

## 7 常见问题

**Q：两个都没勾/没填能不能用？**
能。没有左右骨骼时把「消歧」改为「仅候选一致性」，普通不重叠 UV 的唯一候选可以直接导入。

**Q：目标已经有权重，会被旧权重影响吗？**
默认不会。左右分区只看目标顶点相对自身骨架的位置，不看它原来的权重。旧权重只在你选了「仅未加权」或「混合」时才参与判断。

**Q：模型当前不在绑定姿势怎么办？**
工具直接采集当前网格与参考骨骼位置，不读取绑定矩阵、不切换姿势。请先把模型摆回绑定姿势再操作。

**Q：源和目标可以不在同一位置吗？**
可以。两套模型连同各自骨架各自平移、旋转、统一缩放都不影响结果。但网格单独移动而骨架不动、非均匀缩放会导致参考平面错误。

**Q：左右完全重叠但权重不同，会串侧吗？**
默认消歧按各自骨架的左右参考平面选同侧候选，不会拿对侧权重。同一侧内部仍有多个冲突候选时会记为歧义并保留原权重，不会随便取第一个面。

**Q：导入后某些顶点没变？**
正常保护行为。缺 UV、候选歧义、必要采样缺失都会保留原权重，具体原因见详细报告。

**Q：用「仅候选一致性」导出的文件，之后还能用骨骼分区吗？**
不能，文件里没有左右参考数据。需要换回「骨骼左右 + 候选一致性」重新导出。

## 8 已知限制

- 同侧多层重叠（例如重复配件、上下唇共用 UV 且左右也无法区分）无法自动判断，会报告歧义
- 左右标识依赖命名，部位本名完全不同（`Eye_L` vs `LeftEyeball`）需要改名或依赖歧义报告处理
- 兼容格式只按顶点序号恢复，顶点数相同也不代表点序相同
- UV 重采样在拓扑差异很大时不保证变形视觉完全一致
- 所有功能在 3ds Max 内的实机验收仍在进行，遇到异常请保留状态行与详细报告
